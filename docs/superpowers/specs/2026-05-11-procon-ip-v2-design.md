# procon-ip v2.0.0 — Design Spec

**Date**: 2026-05-11
**Status**: Approved (pre-implementation)
**Implementation branch**: `feature/v2` (to be created)

## 1. Context

`procon-ip` is a TypeScript client library for the ProCon.IP pool controller. The 1.x series is in maintenance mode and accumulates real friction:

- Build is two raw `tsc` invocations driven by separate tsconfig files; no bundler, no source maps, no type-bundle.
- Yarn 1 Classic is end-of-life.
- No test suite; no coverage reporting in CI.
- ESLint config still pulls unused legacy plugins (`eslint-config-standard`, `eslint-plugin-import`, `eslint-plugin-n`, `eslint-plugin-promise`).
- `axios` runtime dep leaks `AxiosError` into public-ish surfaces and adds CVE exposure.
- `docs/` is committed and regenerated by hand.
- Release workflows publish from a long-lived `NPM_TOKEN` secret.
- `.nvmrc` pins a stale `v12.18.4`.
- No DMX512 support, despite the controller exposing it (`/GetDmx.csv` + `/usrcfg.cgi` form payload with `DMX512=1`).

v2.0.0 fixes all of the above in one coherent release. Breaking changes are allowed where they enable best practices; each one is documented in `CHANGELOG.md` with a migration note.

## 2. Goals & non-goals

**Goals**
- Modernise toolchain end-to-end (pkg manager, build, lint, test, release, docs).
- 80% test coverage as a CI gate; 100% as a stretch target on parsers, interpreters, error paths, DMX.
- Add a clean DMX512 module mirroring the proconip-pypi shape.
- Migrate to npm Trusted Publishing (OIDC + provenance attestation), no long-lived `NPM_TOKEN`.
- Move docs to GitHub-Actions-driven Pages deployment; stop tracking `docs/`.
- Document every breaking change in `CHANGELOG.md` (Keep-a-Changelog) with `old → new` migration lines.

**Non-goals**
- New controller endpoints beyond DMX.
- Per-channel DMX streaming (controller only accepts full 16-channel writes).
- Parser-performance work (existing CSV path is fine for poll cadence).
- Hand-written narrative docs alongside the API reference (post-2.0).
- Anything outside the library's HTTP-wrapper purpose.

## 3. Decisions

| Area | Decision | Rationale |
|---|---|---|
| Module output | Dual ESM + CJS, built with **tsup** | Preserves both consumer worlds; one config; ships sourcemaps + bundled `.d.ts`. |
| HTTP client | **Native `fetch`** (Node 20+) | Drops axios runtime dep + CVE surface; modern API; smaller install. |
| Node floor | **20 LTS + 22 LTS** (drop 18) | Node 18 EOL April 2025; matches `fetch` stable; matches 2026 ecosystem. |
| Package manager | **pnpm 9.x** | Strict resolution, fast installs, dominant for new TS libs in 2026. |
| Test runner | **Vitest** + `@vitest/coverage-v8` | Native ESM/TS, fast, Jest-compatible API, built-in coverage. |
| Lint + format | **ESLint 9 flat + Prettier 3** | Already on flat config; drop unused legacy plugins; keep typed `recommendedTypeChecked`. |
| Release flow | **changesets** + **npm Trusted Publishing (OIDC + provenance)** | Industry standard; no long-lived token; SLSA-grade attestation. |
| Docs toolchain | **TypeDoc** (latest), built in CI, deployed to Pages from Actions | Best fit for pure TS API reference; alternatives (Vitepress + plugin, api-extractor, Docusaurus) are overkill until we have hand-written guides. |
| Changelog | `CHANGELOG.md` (Keep-a-Changelog) | Standard; README references it; no embedded changelog block. |
| DMX shape | Mirror proconip-pypi: `GetDmxService` + `DmxService` + `GetDmxData` + `DmxChannelData` | Read-mutate-write idiom; matches existing one-class-per-endpoint convention. |

### Tooling choices, concrete

- **TypeScript 5.7+**, single `tsconfig.json`: `target: ES2022`, `module: NodeNext`, `moduleResolution: NodeNext`, `strict: true`, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true`.
- **tsup** (`tsup.config.ts`): entry `src/index.ts`, formats `["esm", "cjs"]`, `dts: true`, `sourcemap: true`, `clean: true`, `target: "node20"`.
- **ESLint 9 flat** (`eslint.config.mjs`): keep `@eslint/js` recommended, `typescript-eslint` `recommendedTypeChecked`, `eslint-config-prettier`. Drop `eslint-config-standard`, `eslint-plugin-import`, `eslint-plugin-n`, `eslint-plugin-promise`. Move the `no-unsafe-*` and `no-explicit-any` rules from `warn` to `error` once the source rewrite removes the axios-driven `any` leaks.
- **Prettier 3** (`.prettierrc`): unchanged (`printWidth: 120`, `singleQuote: true`, `trailingComma: 'all'`).
- **Vitest** (`vitest.config.ts`): `environment: 'node'`, `coverage.provider: 'v8'`, `coverage.reporter: ['text', 'lcov', 'html']`, `coverage.thresholds: { lines: 80, branches: 80, functions: 80, statements: 80 }`, `coverage.exclude: ['dist/**', '**/*.d.ts', 'examples/**']`.
- **changesets** (`.changeset/config.json`): default config; `access: "public"`, `baseBranch: "master"`, no fixed/linked packages (single-package repo).
- **TypeDoc** (`typedoc.json`): `entryPoints: ["src/index.ts"]`, `entryPointStrategy: "expand"`, `excludeInternal: true`, `out: "site"` (output path; intermediate, never committed), `validation: { invalidLink: true, notExported: true }`, `treatWarningsAsErrors: true`.

### Error model

A new `src/errors.ts` defines:

```ts
export class ProconIpError extends Error {}
export class BadCredentialsError extends ProconIpError {}
export class BadStatusCodeError extends ProconIpError { status: number; statusText: string; }
export class RequestTimeoutError extends ProconIpError { timeoutMs: number; }
export class InvalidPayloadError extends ProconIpError {}
```

`AbstractService` wraps `fetch` and:
- Throws `BadCredentialsError` on 401 / 403.
- Throws `BadStatusCodeError` on any other 4xx / 5xx.
- Throws `RequestTimeoutError` when an `AbortSignal.timeout(timeout)` fires.
- Lets parser-side `InvalidPayloadError` propagate from data classes.

### `AbstractService` rewrite (sketch)

```ts
protected async request(init: RequestInit & { timeout?: number } = {}): Promise<Response> {
  const headers = new Headers(this._requestHeaders);
  if (this._config.basicAuth) {
    headers.set('Authorization', 'Basic ' + btoa(`${this._config.username ?? ''}:${this._config.password ?? ''}`));
  }
  const controller = new AbortController();
  const timeoutMs = init.timeout ?? this._config.timeout;
  const t = setTimeout(() => controller.abort(), timeoutMs);
  try {
    const res = await fetch(this.url, { method: this._method, ...init, headers, signal: controller.signal });
    if (res.status === 401 || res.status === 403) throw new BadCredentialsError(`Auth failed (${res.status})`);
    if (!res.ok) throw new BadStatusCodeError(`HTTP ${res.status}`);
    return res;
  } catch (e) {
    if ((e as Error).name === 'AbortError') throw new RequestTimeoutError(`Request timed out after ${timeoutMs}ms`);
    throw e;
  } finally {
    clearTimeout(t);
  }
}
```

The retry / consecutive-error tolerance behavior in `GetStateService` is preserved verbatim — only the inner HTTP call changes.

## 6. DMX512 module

### `DmxChannelData`

```ts
export class DmxChannelData {
  readonly index: number;            // 0..15
  readonly name: string;             // "CH01".."CH16"
  value: number;                     // expected 0..255 (constructor stores verbatim; clamping in GetDmxData.set)
  constructor(index: number, value: number);
  toString(): string;                // bare integer for payload building
}
```

### `GetDmxData`

```ts
export class GetDmxData implements Iterable<DmxChannelData> {
  constructor(rawCsv: string);                       // throws InvalidPayloadError if not exactly 16 channels
  readonly raw: string;
  [Symbol.iterator](): Iterator<DmxChannelData>;
  at(index: number): DmxChannelData;                 // 0..15, throws RangeError otherwise
  getValue(index: number): number;
  set(index: number, value: number): void;           // clamps [0, 255]; throws RangeError on bad index
  toPostData(): Record<string, string>;              // { TYPE:'0', LEN:'16', CH1_8, CH9_16, DMX512:'1' }
}
```

### Services

```ts
export class GetDmxService extends AbstractService {
  _endpoint = '/GetDmx.csv';
  _method = 'GET' as const;
  async update(): Promise<GetDmxData>;               // GET + parse
}

export class DmxService extends AbstractService {
  _endpoint = '/usrcfg.cgi';
  _method = 'POST' as const;
  async set(data: GetDmxData): Promise<void>;        // form-encodes data.toPostData()
}
```

### Read-mutate-write idiom

```ts
const dmx = await getDmxService.update();
for (const ch of dmx) dmx.set(ch.index, (ch.value + 64) % 256);
await dmxService.set(dmx);
```

## 7. Documented breaking changes (1.x → 2.0)

Each is captured in `CHANGELOG.md` under `## [2.0.0]` with an `old → new` migration line.

1. **Drop Node ≤ 18**. `engines.node` becomes `>=20.0.0`; install warns/refuses on older Node.
2. **Drop `axios` runtime dep**. Errors are now `BadCredentialsError`, `BadStatusCodeError`, `RequestTimeoutError`, `InvalidPayloadError` (all from `'procon-ip'`). Catch sites that previously inspected `error.isAxiosError` / `error.response.status` should switch to the new classes.
3. **Drop deep imports**. `import { X } from 'procon-ip/lib/get-state.service'` no longer works. Use `import { X } from 'procon-ip'`.
4. **Build outputs move**. `lib/` and `module/` replaced by `dist/`. The `exports` map keeps package-root imports stable, so most consumers are unaffected.
5. **Drop `mock-state` from public exports**. Move to `test/fixtures/` if still useful.
6. **`GetStateService.start` callback contract**: parameters `successCallback` and `errorCallback` retained; the `e` passed to `errorCallback` is now `ProconIpError | TypeError`, not `AxiosError`.

Anything else discovered during implementation gets added here before the changesets PR is opened.

## 8. CI/CD

`.github/workflows/` after the cutover:

| File | Trigger | Steps |
|---|---|---|
| `ci.yml` | push/PR to `master`, `develop`, `feature/*` | matrix Node 20 + 22 → `pnpm i --frozen-lockfile` → lint → typecheck → build → test with coverage → upload `coverage/` artifact → post coverage summary to PR |
| `docs.yml` | push to `master`, on release | build TypeDoc with validation flags → `actions/upload-pages-artifact@v3` → `actions/deploy-pages@v4` |
| `release.yml` | push to `master` | `changesets/action@v1`. When the Version Packages PR merges, publish to npmjs (Trusted Publishing, OIDC + provenance) and to GitHub Packages (with the existing name-rewrite step) |
| `codeql.yml` | push to master + weekly schedule | bump `github/codeql-action/*` to v3 latest; language id stays `javascript-typescript` |
| `automerge.yml` | dependabot PR | unchanged behavior; bump action versions |

Common changes:
- All `actions/*` references bumped to current major (`checkout@v4`, `setup-node@v4`, `upload-artifact@v4`, `upload-pages-artifact@v3`, `deploy-pages@v4`, etc.).
- `actions/setup-node` reads node version from `.nvmrc` — but `.nvmrc` is no longer tracked (see §10). For CI we set `node-version` explicitly via the matrix.
- `pnpm/action-setup@v4` with `cache: pnpm`.

### Release flow specifics

`release.yml` publish job:

```yaml
publish:
  runs-on: ubuntu-latest

    name: release
    url: https://www.npmjs.com/package/procon-ip
  permissions:
    id-token: write
    contents: write

    - uses: pnpm/action-setup@v4
```

Trust binding (already configured by user, recorded for future maintainers):
- npm trusted publisher: `ylabonte/procon-ip`, workflow `release.yml`, environment `release`.
- GitHub environment `release`: deployment branch policy restricted to `master`; no required reviewers (single-maintainer); no environment secrets needed.

The legacy `release-npmjs.yml` and `release-github.yml` workflows are deleted in v2.

## 11. Test strategy

- Unit tests for parsers (`GetStateData`, `GetStateDataSysInfo`, `GetStateDataObject`, `RelayDataObject`, `GetDmxData`, `DmxChannelData`).
- Unit tests for `RelayDataInterpreter` bit math.
- Service tests with `vi.spyOn(global, 'fetch')` returning canned `Response` objects covering: success, 401, 403, 5xx, network error, timeout, partial CSV.
- `GetStateService.start()` polling and consecutive-error tolerance covered via `vi.useFakeTimers()`.
- Fixtures live in `test/fixtures/*.csv`; loaded by helpers in `test/helpers/`. No CSV strings inlined into test files.
- Coverage thresholds in `vitest.config.ts`: lines/branches/functions/statements ≥ 80. CI fails below threshold.
- Stretch goal recorded in spec + CHANGELOG: 100% coverage on parsers, interpreters, error classes, and the DMX module.
- `pnpm coverage:report` surfaces uncovered lines for the "find the last 20%" loop.

## 12. Docstring audit

A discrete pre-docs phase, gated before the first v2 `typedoc` build:

1. Enumerate the public surface from `src/index.ts`.
2. For each exported symbol ensure:
   - One-line summary (renders as TypeDoc sidebar / search snippet).
   - `@param` for non-obvious args, with units called out (ms vs s, 0–255, etc.).
   - `@returns` if not obvious from the signature.
   - `@throws` for HTTP / validation errors.
   - `@example` on the most-used methods (`GetStateService.start`, `UsrcfgCgiService.setOn/Off/Auto`, `DmxService.set`, `CommandService.setChlorineDosage`).
   - `@deprecated` migration line for any 1.x symbol kept for compat.
3. Run `pnpm docs:check` (TypeDoc with `--validation.invalidLink --validation.notExported --treatWarningsAsErrors`) until clean.
4. Wire `pnpm docs:check` into `ci.yml` so future broken refs fail PRs.

(Detailed step-by-step plan is the writing-plans deliverable.)

1. **Repo hygiene & in-flight triage** (§13, §10).

8. **Docs**: regenerate via `docs.yml` first run; verify Pages output.

10. **changesets bootstrap**: add changeset for 2.0.0, open Version Packages PR, merge → publish.

## 15. Risks & open questions

- **OIDC trusted publishing** requires npm CLI ≥ 11.5 in CI. Node 22's bundled npm satisfies this; pin if needed.
- **Provenance attestation** requires `--provenance` and a public package — `procon-ip` is public. ✅
- **Pages cutover**: the first `docs.yml` run replaces whatever HTML is currently served; no URL change for consumers.
- **HTTP service coverage**: mocking `global.fetch` reaches all branches without real network; expected ≥ 95%.
- **Downstream impact (`ioBroker.procon-ip`)**: not in this repo. Will need a follow-up PR there to handle new error classes and deep-import removal. `CHANGELOG.md` migration section calls this out explicitly.
- **GitHub Packages publish**: kept (with `sed` rewrite to `@ylabonte/procon-ip`). If we ever decide to drop the GH Packages mirror, that's a separate breaking change for v2.x or v3.

## 16. Acceptance criteria

v2.0.0 ships when all are true:
- [ ] `pnpm i && pnpm format:check && pnpm lint && pnpm typecheck && pnpm build && pnpm coverage && pnpm docs:check` passes locally on Node 20 and Node 22.
- [ ] CI is green on `master` for one full cycle.
- [ ] Coverage thresholds met (≥ 80% all four metrics); achieved coverage recorded in CHANGELOG.
- [ ] Pages deploy from `docs.yml` succeeds and serves the new TypeDoc output.
- [ ] `release.yml` dry-run succeeds (no-op changeset on a throwaway branch demonstrates the publish job reaches the OIDC token-exchange step).
- [ ] `CHANGELOG.md` 2.0.0 section lists every breaking change with migration line.
- [ ] README rewritten: examples updated for new error classes + DMX, points to `CHANGELOG.md` instead of an embedded changelog.
- [ ] No reference in source / tests / published docs to `axios`, `lib/`, `module/`, or `mock-state` from the public surface.
- [ ] Old workflows (`release-npmjs.yml`, `release-github.yml`) removed; new `release.yml` in place; `NPM_TOKEN` secret deleted from repo.
